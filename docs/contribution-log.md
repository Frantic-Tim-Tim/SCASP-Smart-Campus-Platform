# SCASP Contribution Log

This document records the contributions made by Thomas, Majid and Mukuka during the development of the Smart Campus Academic Services Platform (SCASP).

## 1. Contribution Rules

1. Every member should contribute to the project.
2. Contributions should be documented accurately.
3. Tasks should be assigned and tracked.
4. Code should be reviewed before merging.
5. Members should understand the code they contribute.
6. Contributions should be updated regularly.

## 2. Contribution Attribution

The three members contributed collaboratively to the development
of SCASP, although their methods of contribution differed.

Thomas primarily handled direct code implementation, typing,
repository management and integration.

Majid and Mukuka contributed through technical discussions,
solution recommendations, development guidance, testing and
reviewing the implemented features.

Although Thomas performed most of the direct code entry, the
development process involved collaborative problem-solving and
technical input from all three members.

GitHub commit authorship therefore does not necessarily represent
the full extent of each member's contribution. Contributions
are recorded according to the actual work performed.

## 5. Version Control and Evidence

Git and GitHub are used to manage project source code, branches,
commits and pull requests.

GitHub commit authorship primarily reflects the account used to
submit changes. It does not capture all collaborative activities,
such as technical discussions, development guidance, testing and
code reviews. These contributions are therefore documented
separately according to the actual work performed.
