This document records the collaborative and practical contributions made
during the development of the Smart Campus Academic Services Platform.

identifying the academic service problems to address and shaping the

## 3. Practical Implementation History

During implementation, the group experienced computer-resource constraints.
Majid and Wendy did not have suitable computers or laptops available to
independently configure development environments, implement the application
and test it on their own machines.

Consequently, Thomas carried out much of the practical implementation,
including repository development, Java and Maven configuration, module
development, database integration, application-server configuration,
integration, testing and technical documentation.

This implementation arrangement resulted from the group's resource
limitations. It does not exclude Majid or Wendy from the project or disregard
their participation in its collaborative brainstorming and conceptualisation.

## 4. Development Evidence

The practical implementation history is supported by the project repository,
source code, commit history, architecture documentation, test records and
deployment configuration.

The contribution record distinguishes between the group's collaborative
planning contributions and the practical implementation work completed
during development. It does not assign unverified individual coding tasks
to any member.

## 5. Contribution Principles

1. Contributions should be described accurately and fairly.
2. Collaborative planning and conceptualisation should be acknowledged.
3. Practical implementation responsibilities should reflect the actual
   development circumstances.
4. No member should be excluded because of limitations in access to
   development equipment.
5. Repository commits and technical evidence should be used when describing
   specific implementation work.
